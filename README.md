# 技術スタック・プロジェクト構成

本プロジェクトは、Web版およびモバイル版での展開を想定し、開発効率とパフォーマンスを重視したモダンな技術構成を採用しました。

---

## 技術スタックの概要

| 区分 | 技術 | 採用理由・目的 |
| :--- | :--- | :--- |
| **フロントエンド** | Next.js (React/TypeScript) | **Web/モバイル展開の想定**と、**既存のReact開発経験**を活かした開発コスト・工数削減のため。 |
| **モバイル** | React Native (TypeScript) | Web版と同じくReactベースで、効率的にモバイルアプリを展開するため。（実装予定） |
| **バックエンド** | Next.js (API Routes) | Next.jsの機能を利用し、フロントエンドと統合して開発を進めるため。**（実装中）** |
| **状態管理** | Zustand | シンプルで軽量な状態管理ライブラリ。 |
| **データベース** | MySQL | 安定性と信頼性の高いリレーショナルデータベース。**（実装中）** |
| **ORM** | Prisma | TypeScriptの型システムを活用し、SQL文を直接書かずに安全にDB操作を行うため。実行前にDBエラーを検出可能。**（実装中）** |
| **デプロイ** | AWS | ドメイン取得まで含めたインフラ環境として選定。**（実装中）** <br>フロントエンド：AWS Amplify <br> バックエンド：AWS Lambda <br> データベース：Amazon RDS|

## 開発・テスト環境

| 項目 | 技術 | 目的・実装内容 |
| :--- | :--- | :--- |
| **ローカルテスト** | husky | コミット前、プッシュ前にテストを自動実行し、コード品質を保つ。 |
| **リモートテスト** | GitHub Actions | プッシュ時やプルリクエスト時にテストを自動実行し、デプロイ前の品質を担保する。 |
| **タスク管理** | **Dnd-Kit** | タスクの**ドラッグ＆ドロップ機能**を実装するために採用。 |
| **認証機能** | **Firebase** (Authentication) | 認証、DB連携、APIがセットになっており、**実装コストを大幅に抑制**するため。**（実装中）** |

## タスク管理機能の実装詳細

本プロジェクトで実現するタスクのCRUD（作成・読み取り・更新・削除）機能と、リマインダー機能の仕様です。

### 1. タスクの基本属性

* **タイトル**: 必須項目（大文字表示）
* **詳細**: オプション（小文字表示）、表示/非表示の切り替え機能あり
* **完了ステータス**: タスクの完了状態を管理 （実装予定）
* **進捗バー**: タスクの進捗状況を視覚的に表示 （実装予定）

### 2. 入れ子構造（階層管理）

タスクの親子関係は、**JSON階層**にて管理します。

### 3. リマインダー機能 (実装予定)

以下のリマインダー機能を実装します。（※いずれか１つを選んで設定する）

* **A. 期日**: 特定の**日付と時間**を指定
* **B. 繰り返し (定期)**: **毎日**、**毎週**など、定期的な繰り返し設定
* **C. 繰り返し (リセット)**: タスク完了時に期日を**特定期間後にリセット**する設定
